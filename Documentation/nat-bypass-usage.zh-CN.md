# Xash3D FWGS 中的 NAT 穿透功能
由于 IPv6 没有像我们希望的那样普及，NAT（网络地址转换）仍被许多互联网服务提供商积极使用，以缓解 IPv4 地址耗尽的问题。简而言之，他们使用一个 IPv4 地址，并通过端口技巧来代表该地址后面的许多其他用户。

但这给用户带来了问题：他们无法再接受直接的传入连接。这意味着如果你在运营商的 NAT 后面并尝试搭建 Xash3D FWGS 服务器——将没有人能够连接到它，并且服务器不会显示在公共服务器列表中。

## 是否可以避免这个问题？
在大多数情况下，可以通过 UDP 打洞来绕过 NAT，Xash3D FWGS 也使用此方法。但此方法并不能保证 100% 工作——它取决于服务器和客户端双方的 NAT 配置，无法控制。

首先，服务器不能在对称型 NAT 后面。你可以在 [此页面](https://www.checkmynat.com/) 检查你的 NAT 类型。
如果在此测试中得到"Symmetric NAT"结果，意味着你无法使用当前网络连接搭建公开可用的服务器。

以下是不同 NAT 类型兼容性的详细方案，说明不同 NAT 类型的用户是否可以互相连接。
行为是行中的客户端 NAT 类型，列中的服务器 NAT 类型：

| *NAT 类型* | Full Cone | Restricted Cone | Port Restricted Cone | Symmetric |
| -------------------- | --------- | --------------- | -------------------- | --------- |
| Full Cone | ✔️ | ✔️ | ✔️ | ✔️ |
| Restricted Cone | ✔️ | ✔️ | ✔️ | ✔️ |
| Port Restricted Cone | ✔️ | ✔️ | ✔️ | ❌ |
| Symmetric | ✔️ | ✔️ | ❌ | ❌ |

## 如何使用 NAT 穿透功能？
如果你在游戏中启动服务器，需要在屏幕左下角启用"*Use NAT Bypass instead of direct mode*"选项。

如果你启动的是专用服务器，应在 server.cfg 文件中添加控制台变量 `sv_nat 1`，或在服务器启动参数中添加 `+sv_nat 1`。

如果你需要连接到 NAT 后面的服务器，服务器浏览器中有专门的 *NAT* 标签页用于此类服务器。请注意，将 NAT 服务器添加到收藏夹或以其他方式手动存储是无用的，因为它的地址和端口会变化。
